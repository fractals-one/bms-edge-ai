## Description

The **STSW-L9961BMS** software package demonstrates the features and performance of the **L9961** industrial Battery Management System (BMS) IC. It is designed for the **STEVAL-L99615C** evaluation kit, which consists of:

- **NUCLEO-G071RB** development board (STM32G071RBT6 microcontroller)
- **L9961** expansion board (plugged on top of the Nucleo board via morpho connectors)
- Support for battery packs with up to **5 cells**

### STEVAL-L99615C Evaluation Kit Details

| Component | Details |
|-----------|--------|
| **L9961 BMS IC** | 5-cell Li-ion monitoring, high-precision ADC (cell/stack voltage, NTC temp), CSA with Coulomb counter, passive cell balancing (all cells simultaneously), dual pre-driver for charge/discharge MOSFETs, OV/UV/OT/UT/overcurrent/short-circuit protection, I2C interface, NVM for safety configs, VFQFPN-32 package |
| **NUCLEO-G071RB** | STM32G071RB (Cortex-M0+ @ 64 MHz, 128KB Flash, 36KB RAM), ST-LINK/V2-1 debugger, USB connector |
| **Expansion Board Features** | 5-cell battery pack connector, embedded battery simulator, onboard fuse emulator, charge/discharge MOSFETs, NTC temperature sensor |
| **Stacking** | L9961 board stacks on Nucleo via morpho connectors (CN7, CN10) |
| **Interface** | I2C (L9961 ↔ MCU), UART @ 115200 baud (MCU → Tera Term) |

The STSW-L9961BMS data acquisition (specifically **app_bms_demo1.c**) provides real-time V, I, T data for AI-based State of Charge (SoC) and State of Health (SoH) estimation using **ST Edge AI (STM32Cube.AI)**:

| Property | Value |
|----------|-------|
| **Project** | cubeAI |
| **Tool URL** | https://www.st.com/en/development-tools/stedgeai-cubeai.html |
| **Model** | TensorFlow Lite (net_model) |
| **Input** | Voltage, Current, Temperature (from app_bms_demo1.c) |
| **Output** | SoC (%), SoH (%) |
| **Network Nodes** | 10 |
| **MACC Operations** | 4,651 |
| **Weights Size** | 17.4 KB |

### Data Flow

```
Battery Pack → L9961 (ADC/CSA) → I2C → STM32G071RB → AI Inference → SoC/SoH → UART → Tera Term
```

### AI Model Training Pipeline

The model was trained using **real-world battery cycling data**:

| Step | Tool | Details |
|------|------|---------|
| Data Processing | PyProBE | Raw CSV → column mapping → Parquet → SOC/SOH computation → labelled CSV |
| Model Training | TensorFlow/Keras | Conv1D architecture: Input(3) → Norm → Reshape → Conv1D(32) → GAP → Dense(64) → Dense(32) → Dense(2) |
| Training Params | — | Adam optimizer, MSE loss, 10 epochs, batch size 32 |
| TFLite Export | TFLiteConverter | `NET_model.tflite` |
| MCU Deployment | STM32Cube.AI | `.tflite` → analyse → optimise → generate C/H → build → flash |

> **Note:** LSTM/GRU architectures were evaluated but are not compatible with the Cortex-M0+ target constraints. Conv1D + Dense was selected.

### Post-Processing (in `app_bms_demo_ai_v2.c`)

| Step | Description |
|------|-------------|
| Saturation | Clamp SoC/SoH to [0, 100]% |
| Moving Average | 10-sample moving average filter |
| Output | Display both raw and averaged values |

### Build Architecture

The project uses a common API pattern (`APP_BMS_Init`, `APP_BMS_Start`, `APP_BMS_Task` in `app_bms_api.h`). Each demo `.c` file implements these functions. The build configuration selects which demo by excluding other demo `.c` files via `sourceEntries` in `.cproject`. `main.c` simply calls the common API.

### How to Build & Run AI Demo

1. Close and reopen project in STM32CubeIDE
2. Right-click project → **Build Configurations** → **Set Active** → **STSW-L9961BMS_DemoAI**
3. Build: `Project` → `Build Project` (Ctrl+B)
4. Debug: Right-click `STSW-L9961BMS_DemoAI.launch` → **Debug As** → **STM32 C/C++ Application**
